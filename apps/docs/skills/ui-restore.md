# UI 还原（Figma MCP + 智能体闭环）

> 核心思路：不是"把设计稿截图发给 AI"，而是让智能体（ZCode/Claude Code 这类 harness）通过 **Figma MCP** 自己拉取画板的结构化数据 → 按项目约定生成组件 → 起 dev server 截图与设计稿对比 → 自己迭代修。人在环上只做两件事：给 Figma 链接、验收。

## 什么时候用

- 新页面开发：设计稿定了，从零还原
- 改版：新设计稿对已有页面做改动（先让 AI 对比新旧结构，只改差异）
- 组件级还原：一个卡片/表单区块的精细化还原

## 前置配置（一次性，二选一）

### 路线 A：Figma 官方 Dev Mode MCP（数据最全，需 Figma 付费席位）

1. Figma 桌面客户端打开目标文件，启用 **Dev Mode MCP Server**（本地服务，默认 `http://127.0.0.1:3845/mcp`）
2. 注册到 ZCode：用户级 `~/.zcode/cli/config.json` 的 `mcp.servers` 下加（或 Settings → MCP 界面添加）：

```json
{
  "mcp": {
    "servers": {
      "figma-dev-mode": {
        "type": "http",
        "url": "http://127.0.0.1:3845/mcp"
      }
    }
  }
}
```

### 路线 B：社区 Framelink（figma-developer-mcp，只需 Figma REST API key）

1. Figma 账号设置里生成 personal access token（只读即可）
2. 注册到 ZCode（stdio 型）：

```json
{
  "mcp": {
    "servers": {
      "figma-context": {
        "command": "npx",
        "args": ["-y", "figma-developer-mcp", "--figma-api-key=你的KEY", "--stdio"]
      }
    }
  }
}
```

> 密钥纪律：REST key 别写进会提交到仓库的工作区配置——放**用户级**配置或环境变量。配置后重启会话，Settings → MCP 里看到已连接即成。

## 工作流提示词（复制即用）

```text
把这份 Figma 设计稿还原成代码，技术栈 Vue3 + TS + Element Plus（按你实际项目改）。

【步骤——严格按顺序】
1. 先用 Figma MCP 拉取节点信息：不要直接生成代码，先给我
   ① 画板结构树（区块划分）② design tokens（颜色/字体/间距变量）③ 用到的图标与图片清单
2. 对照我项目的组件库清单：【列出可复用组件：BaseTable/BaseDialog/…】，声明每个区块复用哪个
3. 按区块生成代码：布局用语义化 flex/grid；颜色/字号/间距引用设计 tokens 而不是硬编码；
   图标走项目图标库；交互（hover/点击/loading）按常见惯例补齐，拿不准的先问我
4. 生成后启动 dev server，用浏览器对还原页截图，与设计稿逐区块对比，
   输出「还原度差异清单」（布局/间距/颜色/字号/圆角各差多少），然后自己迭代修正
5. 一个区块验收通过再进下一个——不要一次性还原整个画布

【约束】
- 交互行为设计稿里没有：跳转/接口都先 mock，接口字段问我
- 不要手写项目里已有组件的替代品，复用优先
- 中文字体/特殊图标缺失时明确告诉我缺什么资源

【Figma 链接】
<粘贴画板/节点链接>
```

## 使用要点（都是踩过的坑）

- **先要结构 + tokens，再要代码**：直接说"把这页变成代码"会得到一份硬编码样式的死页面，改起来比重写还贵
- **复用清单必须人工给**：不声明的话 AI 会手写 div 顶替你所有的 Base 组件
- **截图对比是闭环的关键**：harness 有浏览器能力时，"生成 → 截图 → 差异清单 → 修"让它自己跑，人只验收最终差异清单
- **一屏一屏来**：整画布一次还原 = token 超限 + 每个区块质量都下降
- MCP 返回的是**结构化描述**不是像素级 CSS：间距/字号以 tokens 为准，别要求 1:1 像素（那是设计稿工具的事）
- **交互是设计稿的盲区**：点击跳转、接口字段、异常态设计稿里都没有——AI 会编造，必须人工确认
- 图标/切图缺失提前说：让 AI 列出"缺的资源清单"比让它用占位符硬凑好

## 验收清单（还原度）

- [ ] 布局结构（区块划分/栅格/对齐方式）
- [ ] 间距体系是否来自设计 tokens（不是随机 px）
- [ ] 颜色/字体/圆角与 tokens 一致
- [ ] 交互态：hover / loading / 空数据 / 报错
- [ ] 响应式表现（设计稿没给的断点按惯例处理并说明）
- [ ] 无 AI 编造的交互或接口
