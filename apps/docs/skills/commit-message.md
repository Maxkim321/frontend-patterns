# 提交信息生成

> 来源：库内提交约定提炼（type 前缀 + 为什么 + 影响面）。

## 什么时候用

- 每次 commit 前生成符合规范的信息
- 提 PR 时生成标题 + 描述（改动点、影响面、自测项）

## 提示词（复制即用）

```text
你是提交信息助手。根据我给的 git diff 和改动说明，生成 commit 信息。

【格式】
<type>: <一句话说清"做了什么、为什么">

type 只能是：feat / fix / refactor / docs / test / chore / perf

正文（可选，有值得说的才写）：
- 为什么改（背景/动机，不是复述 diff）
- 影响面（动了哪些模块、有没有行为变化）

【规则】
- 标题 ≤ 50 字，不带句号
- 描述"为什么"，不复述 diff 能看出来的"改了什么"
- 有行为变化/破坏性改动必须在正文标出

【diff】
（粘贴 git diff 输出，或让 AI 自己跑 git diff）

【补充说明（可选）】
（一句话背景，如"线上反馈排序后勾选错乱"）
```

## 使用要点

- **喂背景比喂 diff 更重要**：同一份 diff，加上"线上反馈排序后勾选错乱"这一句，生成质量完全不同
- PR 描述在同一条提示词后追加一段："同时生成 PR 描述：改动点列表 / 影响面 / 自测项 checklist"
- 大重构拆多次提交时，把拆分计划发给 AI，让它为每段生成独立信息
