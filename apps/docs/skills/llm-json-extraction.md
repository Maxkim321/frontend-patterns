# LLM 结构化抽取

> 来源：form-wizard 智能报价实战（"一句话采购需求 → 抽取报价要素预填表单"），经真实模型（glm-5.3-flash）与浏览器全链路验证。

## 什么时候用

- 用户一句话描述需求，系统抽出结构化字段预填表单
- 工单/邮件/聊天记录 → 结构化工单字段
- 意图识别 + 槽位抽取（对话系统第一跳）

## 提示词（复制即用）

```text
你是【业务】信息抽取器。从用户描述中抽取字段，严格输出一个 JSON 对象
（禁止 markdown 代码块、禁止解释文字），schema：
{"字段1":"枚举值A|枚举值B|null","字段2":数字或null,"字段3":"字符串或null"}

规则：
1. 枚举字段只能取给定的枚举值；用户说的不在枚举里就填 null，【不要编造】
2. 抽不到的字段填 null
3. 用户一句话可能包含多个字段，逐个抽
4. 数字字段输出 JSON number，不是字符串

【枚举与归一对照】
- 品类：用户说"私有化部署/私有化" → "私有化"；"旗舰版/智能体平台-旗舰版" → "旗舰版"（按此表归一）
- 部署环境：阿里云 / 华为云 / 本地 IDC（"本地IDC"→"本地 IDC"）

【用户描述】
想采购 60 件私有化部署，放在本地 IDC，3 节点集群，含一年维保
```

## 使用要点

- **三道防线必须都有**（实战教训）：
  1. 提示词层：枚举 + "不要编造" + 归一对照表
  2. 解析层：**宽容解析**——剥掉 ```json 围栏再 parse（模型经常无视"禁止代码块"）；从首个 `{` 到最后一个 `}` 截取
  3. 代码层：**按 value 白名单过滤**——模型返回"私有化部署"而表单 value 是"私有化"，要有一张归一映射表；映射不上的字段直接丢弃，绝不让编造值进表单
- 需要严格 JSON 时可试 `response_format: { type: 'json_object' }`（部分接口支持），但解析层防线照样要留
- 抽取结果进表单前先**白名单过滤 + 枚举归一**，然后只 prefill 可见字段——两个字段互相依赖时，先抽到的会改变后面字段的可见集合
- 温度给 0.1~0.2（抽取是确定性任务，不要 0.7）
- 抽不到就让模型填 null 并在代码里丢弃——**"没抽到"和"抽错了"都远好于"编造一个像样的值"**
