# Agent 槽位收集提示词

> 来源：对话式报价实战（Agent 像顾问一样逐项追问、选项内嵌在对话气泡里，经真实模型三轮对话验证）。

## 什么时候用

- AI 产品里的"对话式表单"：Agent 像销售顾问一样逐项收集信息，收集齐出结果
- 客服工单创建、需求收集、配置开通等"结构化输入"的对话化场景

## 提示词（复制即用）

```text
你是【业务】的收集顾问，用对话逐项收集报价槽位。

【知识库】（把业务规则写进来，模型会用它组织话术）
- 品类单价：标准版 8 万、旗舰版 15 万、私有化 30 万、服务 5 万
- 数量 ≥50 有阶梯 85 折；私有化必须确认部署环境；服务必须确认周期

【已收集槽位（JSON）】
{{slots}}

【每轮规则】
1. 用户最新话语可能一次给出多个槽位，能抽的都抽
2. 若还有必填槽位缺失，reply 里只问最关键的那一个；
   该问题适合选择就给 options（2~4 个候选，value 与槽位取值一致），不适合就 null 让用户自由回答
3. 严格输出一个 JSON 对象（禁止 markdown 代码块）：
{"extracted":{"category":"A|B|null","quantity":数字或null,...},
 "reply":"话术","slot":"options 对应的槽位名或 null","options":[...]或 null}
4. 抽不到的槽位填 null，不要编造；不要重复问已收集的槽位
```

前端每轮做的事：`extracted` 合并进槽位 → 渲染 `reply` 文本 → `options` 非空渲染成**内联选项芯片**（点选即回复）→ **本地判定槽位是否收集齐**（齐了出结果卡片，不信任模型）。

## 使用要点

- **槽位齐不齐前端本地判定，绝不信任模型**：required 槽位真的有值才算齐；模型说"信息收集完整"不算数
- **options 必须带显式 slot 名**（写哪个槽位），点选时按它写值——靠回复文本里的关键词猜槽位必错
- **开场轮不要只发 system**：火山 Ark 会拒绝"只有 system 没有 user 消息"的请求（InvalidParameter 400）——开场用前端本地固定话术 + 选项芯片，等用户回应后再进模型轮
- **知识库写进系统提示词**：单价、阶梯规则——模型会用它组织追问话术（"达到 50 台还有 85 折"），比干巴巴问"数量多少"体验好一个档次
- JSON 输出解析要宽容：剥 ``` 围栏、取首尾花括号截取（见 [LLM 结构化抽取](/skills/llm-json-extraction)）
- 每轮把已收集槽位的 JSON 现值发给模型——它才知道哪些不用再问
