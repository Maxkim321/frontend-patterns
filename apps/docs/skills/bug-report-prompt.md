# 报错排查喂料模板

> 来源：库内调试实战（Worker 静默失败、链接错位、Ark 400 等排查的复盘）。AI 排查的准确率几乎完全取决于你喂的上下文结构——这份模板就是"一次喂对"。

## 什么时候用

- 控制台报错看不懂 / 功能"不报错但不工作"（灵异 bug）
- 想让 AI 给出定位方向而不是一堆"可能的原因"

## 提示词（复制即用）

```text
你是资深前端排查助手。按下面的结构化信息定位问题，要求：
1. 先给出最可能的 1~2 个根因假设，按可能性排序
2. 每个假设给出【验证方法】（具体到在哪个文件打什么日志/用什么面板看什么）
3. 不要给我"可能是多种原因"的泛泛清单——基于我给的信息做推断
4. 信息不足以推断时，明确列出"还缺什么信息"，让我去取

【现象】
（一句话：期望什么 / 实际什么。例：勾选 Worker 模式后表格空白，无任何控制台报错）

【环境】
（浏览器/运行环境、框架版本。例：Vue3 + VitePress，ZCode 内嵌 webview，正常 Chrome 未复现）

【复现步骤】
（1. … 2. … 3. …）

【已排除的可能】
（很重要！例：已确认数据源有值、已确认事件触发、组件已挂载）

【相关代码】
（只贴怀疑的文件/函数，整页粘贴会稀释注意力）

【报错/日志原文】
（控制台完整输出；"没有任何报错"也要写明——静默失败本身是关键线索）
```

## 使用要点

- **"已排除的可能"是最高价值字段**：告诉 AI 你验证过什么，它就不会让你重复走弯路
- **静默失败要明说**："没有任何报错"本身就是强线索（Worker 静默失败、Promise 吞错、CSS 遮挡都是这类）
- 环境差异是黄金线索："A 浏览器能跑 B 不能跑"直接指向环境 API 差异（如 webview 无下载管理器、CSP 拦 Worker）
- AI 给出假设后，**按它的验证方法取回新信息再喂回来**——排查是多轮对话，不是一次提问
